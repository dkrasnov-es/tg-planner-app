# MiniApp планировщика: v1 и v2

Две независимые точки входа на существующем GitHub Pages:

- `/` — бот v1, база `/home/claude/projects/tg_planner/planner.db`.
- `/v2/` — бот v2, база `/home/claude/projects/tg_planner_v2/planner.db`.

## Независимые релизы из общего исходного кода

`app.js` — общий исходный код интерфейса. Каждая точка входа загружает свой
`config.js`, который закрепляет неизменяемый файл `releases/<variant>/<release>/app.js`.
`variants/v1.json` и `variants/v2.json` фиксируют исходник, версию протокола и SHA-256.
Обновление общего исходника само по себе не переключает ни один новый клиент.

Выпуск изменения сначала для v1:

```sh
python3 tools/release.py --variant v1 --release 2026-11-13-example
python3 tests/smoke.py
python3 tests/focus.py
```

Чтобы перенести проверенное изменение в v2, отдельно собрать и проверить v2:

```sh
python3 tools/release.py --variant v2 --release 2026-11-13-example
python3 tests/focus.py
```

После проверки коммитятся исходник, новые артефакты, конфигурация выбранной версии
и её манифест. Публикация идёт существующим способом: `main` → GitHub Pages.
Конфигурация другой версии остаётся прежней. Старые релизы нельзя перезаписывать;
для отката вернуть предыдущие `config.js` и манифест выбранной версии.

Для специфичной логики допустим отдельный исходник, например
`variants/v2/app.js`, и `--source variants/v2/app.js`. Он закрепляется тем же
механизмом. Общие исправления переносятся обычным Git-патчем в обе ветки исходников;
различия не требуют автоматического обновления другой версии. Простые различия
названия и идентификатора задаются конфигурацией, без копирования бизнес-логики.
Один хостинг означает общую доступность сайта, но не общие данные или релизы.

## Разделение данных и совместимость

Каждый бот имеет свои токен, разрешённый чат, SQLite, состояние и процесс.
Они не импортируют код и не читают базу другого бота. Python-слой MiniApp в v2
перенесён из v1, при этом NLU, повторяющиеся задачи и ритуалы v2 сохранены.

Telegram CloudStorage и browser localStorage разделены по идентификатору бота.
v1 сохраняет старые ключи для совместимости; v2 использует собственные ключи.
Снимки и пакеты изменений содержат `instance`. Клиент отклоняет чужой снимок,
сервер отклоняет чужой пакет до записи в базу, даже при совпадающих ID задач.
Пакеты без `instance` допускаются только v1 для совместимости со старым клиентом.
`v: 1` обозначает версию протокола, а не номер бота.

Запуск — из reply-кнопки «📱 Планировщик»; `/app` обновляет снимок.
Сохранение использует существующий `Telegram.WebApp.sendData`. Кнопка меню
Web App, открывающая приложение иным способом, не подставляется вместо reply-кнопки:
транспорт сохранения зависит от способа запуска. Для v2 также доступны `/start`
и `/menu`. Большие снимки передаются существующим фрагментированным синком.

## Фокус дня

Каждая карточка содержит «Редактировать» и «Удалить». Эти кнопки не переключают
выполненность карточки. Изменения остаются в буфере до «Сохранить изменения».
Удаление означает архивирование; данные задачи сохраняются в истории базы.

После удаления свободное место сразу заполняется следующей подходящей задачей.
Кандидаты: на сегодня, просроченные или P1; удалённые и выполненные исключаются.
Учитываются текущие проект и приоритет, а также несохранённые правки.
Без фильтров сохраняются места оставшихся задач; замена выбирается по скорингу
бота: дни просрочки + балл за сегодня + балл за P1, затем приоритет, дата и ID.
Под фильтрами сохраняется сортировка v1: приоритет, затем дата.
Если кандидатов нет, карточек становится меньше. При переносе задачи за пределы
критериев фокус тоже обновляется. После серверного сохранения он пересчитывается
из текущей базы.

## Проверки

```sh
python3 tests/smoke.py
python3 tests/focus.py
python3 tests/test_releases.py
```

Браузерные тесты используют заглушку Telegram и искусственные данные.
`focus.py` проверяет обе реальные точки входа, сохранение буфера при перезагрузке,
автозамену, фильтры, запрет чужих снимков и разделение хранилищ на одном origin.
Серверные тесты `tests/test_ui.py` в каждом проекте бота используют временную SQLite.
